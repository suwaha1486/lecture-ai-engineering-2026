## 演習

- 基準別の一致率（直す前）：根拠　7/9（要確認 1），範囲　10/10，ヒント　10/10，分かりやすさ　8/10，回の表示　6/10（総合 6/9，coverage 90%）
- 要確認の件数（直す前）：1 件（#05 根拠．「用語集にない語を，用語集にないと伝えたうえで一般的に説明する」が「まだ決めていないこと」に当たるため）
- 直した基準と，書き足した方針：根拠（grounding）．「用語集にない語を，『用語集にはない』と伝えたうえで一般的に説明するのは，断定ではない（pass）」を書き足し，「まだ決めていないこと」からこの論点を消した．用語集にないことを明示していれば，利用者は根拠の範囲を区別できるので，合格とした
- 基準別の一致率と要確認の件数（直した後）：根拠　7/10，範囲　10/10，ヒント　10/10，分かりやすさ　7/10，回の表示　6/10（総合 6/10，coverage 100%）．要確認は 0 件．#05 の根拠は unsure → pass になり，自分のラベル（pass）と一致した
- 講師のラベルと自分のラベルで判定が違った項目と，そう判定した理由：
  - #05，#07，#08，#09 回の表示：「末尾に第N回があるか」ではなく，表示が適切かで判定した．講座と関係のない質問（#07 天気，#09 空の質問）は「なし」と表示するのが正しいと考えて pass にした．#05 は用語集から分からないのに「第4回」と付けているのが不適切だと考えて fail にした
  - #02，#04 分かりやすさ：#02 は自分にとって分かりにくかったので fail にした．#04 は繰り返しがあったが，丁寧な説明で分かりやすいと感じたので pass にした．どちらも主観による判定で，講師と割れた
  - #10 根拠：「講義が近づいてから追加される予定」という説明に納得してしまい，pass にした．講座は全13回で，予定は用語集にも要点データにもないので，根拠のない断定として疑うべきだった
- 気づき・疑問：
  - 回の表示は「末尾に第N回があるか」という機械的な規則なのに，自分は回答全体の良し悪しや表示の妥当さで判定してしまい，講師との一致が 6/10 と最も低かった．1 つに決まる基準を人に任せるとぶれるので，コードで判定する理由が分かった．一方で，関係する回がない質問に「なし」と答えるのは妥当で，今のコードの規則ではそれが fail になる．規則が硬すぎるので，「講座外の質問では『なし』も合格」のように規則側を直す余地があると思う
  - #10 の根拠は，自分は見逃したが LLM（と講師）は「講義が近づいてから追加される予定」を根拠のない断定として fail にした．人のラベルも正解とは限らない
  - rubric.md を 1 行直しただけなのに，直していない #06 根拠と #08 分かりやすさの判定も pass → fail に変わった．どちらも LLM の理由を読むと，ヒントや範囲の失敗を別の基準に持ち込んでいる（「基準は独立に見る」と書いてあっても観点が混ざる）．temperature 0 でも判定が変わるので，1 回の実行だけで「直した効果」を言い切るのは難しい

## 宿題

- 取り組んだレベル：基礎
- やったこと：採点のモデル（`AIE_MODEL`）を `gemini-3.5-flash-lite` から `gemini-3.5-flash` に替えて再実行した．rubric.md（演習で根拠の方針を書き足した後のもの）と labels.jsonl は同じ．結果は `lectures/04/judge_result_flash.json` に保存した．演習で LLM が別の基準の失敗を持ち込む「観点の混ざり」が出たので，講義の「より強いモデルで採点する」が効くかを確かめたかった
- 結果：

  | 基準 | flash-lite | flash |
  |---|---|---|
  | 根拠 | 7/10 | 8/10 |
  | 範囲 | 10/10 | 10/10 |
  | ヒント | 10/10 | 10/10 |
  | 分かりやすさ | 7/10 | 8/10 |
  | 回の表示（コード） | 6/10 | 6/10 |
  | 総合 | 6/10 | 6/10 |
  | 要確認 | 0 件 | 0 件 |

  - flash-lite で出た観点の混ざり 2 件（#06 根拠を「宿題のコードを出した」で fail，#08 分かりやすさを「役割に反する要求に応じた」で fail）が，flash では出ず pass になった
  - #10 根拠は両モデルとも fail（「追加される予定」を根拠のない断定と判定）．講師のラベルとも一致する
  - #08 根拠は両モデルとも fail のまま．flash の理由は「参照に用語集のエントリがないのに，用語集の内容として出力している」で，参照に照らせないことを根拠の不足とみなしていた
  - 総合が変わらないのは，総合に入る「回の表示」で自分のラベルとコードの判定が 4 件ずれているため
- 気づき・疑問：
  - 強いモデルにすると，基準を 1 つずつ独立に見る指示を守りやすくなり，講義の「生成とは別の，より強いモデルで採点する」と合う結果になった．ただし各モデル 1 回ずつの実行で，演習では同じモデルでも判定が揺れたので，差が 1 件ずつでは揺れの範囲かもしれない．言い切るには同じ条件で数回回して比べる必要がある
  - #08 根拠のように，採点に渡す参照（用語集のエントリ）が足りないと，強いモデルでも判定が人とずれる．採点の精度はモデルだけでなく，渡す参照の作り方にも左右される
  - flash は無料枠のレート制限に当たりやすく，10 件でも 1 回目は途中で止まった．強いモデルは精度が上がる一方で，費用や速さの面では不利になる
